# VendorGuard：供应商材料审查 Agent

> 更新：2026-09-08。当前实施基线，替代原供应商准入与采购例外平台方案。
> 面向个人学习与 AI Agent / AI 应用开发求职；下述能力是交付目标，当前实现见 [项目上下文](../PROJECT_CONTEXT.md)。

## 要解决的问题

采购人员拿到供应商材料后，需要找出缺项、检查声明有效期，并找到相关制度说明依据。VendorGuard 用一个 Agent 辅助完成初审，输出可核对的报告。演示使用自制材料和教学制度。

产品主线：

```text
提交材料与审查请求 -> Agent 选择并调用工具 -> 查看结果
                         -> 缺信息时追问，收到补充后继续
                         -> 形成带引用的报告 -> 用户确认或要求重查
```

最终产物是初审报告，不是准入决定、AVL 更新或采购审批。

## 第一版范围

| 保留的能力 | 限定范围 |
| --- | --- |
| 材料输入 | 一种自制、固定版式、可提取文本的 PDF；不处理扫描件、图片或多种表格 |
| 信息提取 | 单个供应商、证照声明日期、材料清单；保留原始页码，缺失值留空 |
| Agent | 一个审查 Agent，根据任务和工具结果选择后续调用、检索问题或追问 |
| 确定性校验 | 复用两条现有规则和日期计算；不扩展通用规则语言 |
| RAG | 小语料、单路向量检索、来源定位、无依据说明 |
| 人工参与 | 补充信息、确认报告或要求重查；不接正式准入审批 |
| 页面 | 一个审查工作台，展示材料、对话、工具执行结果和报告 |
| 评估 | 少量固定案例与真实模型运行记录，可复现错误和修复结果 |

结构化样例只服务第一阶段调试；最终演示需要实际读取 PDF，不把模拟解析称为真实解析。已有案件、审批、认证与审计实现保留，但不要求补齐企业流程后才能交付上述主线。

## Agent 与工具

Agent 主导的是任务执行选择：决定先读哪些材料、针对什么问题检索、是否需要用户补充。它可以根据工具结果调整下一步，不要求所有请求固定经过相同节点。

第一版只暴露三个业务工具，名称为待实现接口：

| 工具 | 输入与输出 | 执行边界 |
| --- | --- | --- |
| `read_material` | 当前会话的材料 ID -> 带页码的文本 | 使用成熟 PDF 解析库；仅访问用户已提交的材料 |
| `check_materials` | 结构化事实及来源 -> 缺项、日期计算与规则结果 | Pydantic 校验；复用规则纯函数，不写案件状态 |
| `search_policy` | 查询文本 -> 制度片段、来源 ID 和定位 | 服务端限定有效语料；空结果如实返回 |

事实提取由同一个模型完成，先经 Schema 校验再交给工具。缺少日期时不能计算，缺少某材料的状态不能由模型补造。规则结果与模型解释分开保存。

执行器负责工具白名单、参数校验、超时、循环停止和最终输出检查。每次用户提交最多 8 轮模型调用、累计最多 12 次工具执行，达到上限即停止并显示原因；追问结束本次执行，用户回复后再开始下一次。M1 落地这些上限并通过测试验证。

最终报告由服务端检查：事实有来源；支持范围内的校验已执行；引用存在于本次检索结果；未检索成功时不能声称有制度依据。引用存在性可自动验证，引用是否支持结论还需固定案例人工检查。报告校验失败最多纠正一次，仍失败则明确报错。

材料和检索正文作为待分析数据，不允许其中的文字改写工具权限或执行要求。模型不获得批准供应商、任意读文件或修改数据库的工具。

## RAG 核心范围

RAG 与 Agent 同为项目主线。首版聚焦找到适用依据、核对引用和分析失败案例；实现按下列边界收缩，不把知识治理平台作为前置条件。

| 环节 | 首版实现 | 暂停内容 |
| --- | --- | --- |
| 语料 | 两份现行内部制度，固定演示日期为 2026-09-01 | 扩充法规库、任意历史日期回放 |
| 分块 | 复用内部制度解析，按章节和表格行保留引用位置 | 扩展法规章、节、条、款、项解析 |
| 存储 | 一份扁平片段清单和本地 embedding 缓存 | 四层实体入库、不可变表、版本血缘与增量入库服务 |
| 检索 | 单路向量检索，固定返回最多 5 个候选 | ParadeDB/BM25 接入、RRF、reranker |
| 引用 | 返回原文与来源，检查引用 ID；依据不足时明确说明 | 独立 EvidenceEngine、证据槽位持久化和审批状态联动 |
| 验证 | 8 个固定问题、一次真实失败分析 | 多指标评测平台、大屏和在线质量承诺 |

两份制度是 `demo_supplier_admission_policy_v2` 和 `demo_supplier_required_documents_policy_v3`。服务端以明确的版本清单限定候选，展示演示日期与适用范围；旧版本和外部法规保留在仓库作为负例，不进入首版的直接依据集合。固定版本过滤不等于已经实现通用适用性判断或历史版本检索。

准备语料时只读取选中版本的正文与清单元数据，复用 `parse_policy_edition()` 生成章节和表格行片段；不要求 `parse_frozen_corpus()` 全量解析成功。保留现有解析器和测试，不为简化重新写一套分块算法。运行检索只消费扁平片段，字段包括稳定 ID、正文、标题、制度版本、定位和原文路径；这些是检索数据，不新增领域数据库实体。

embedding 缓存在本地，记录模型与对应文本；模型或正文变化时整体重建。使用现成数值库做精确相似度计算，不要求向量数据库。Agent 使用 `search_policy(query)` 获取片段，可在原有调用预算内改写问题再次搜索；不新增独立检索 Agent。

相似度最高的片段也可能无法支持结论，分数不能直接表示“证据充分”。程序检查引用 ID 与原文是否对应，Agent 根据内容解释或指出依据不足；自然语言结论是否被引用支持，由固定案例人工核对。无需为了拒答先引入第二个审校模型或复杂置信度系统。

首版评测从原 `data/evals/rag_phase1.json` 选以下 8 题，实施时用题目 ID 引用原记录，保留金标准与禁止引用，不改写原数据：

- 正常检索：`rag_phase1_current_admission_license_consistency`、`rag_phase1_critical_material_quality_certificate`、`rag_phase1_standard_components_quality_certificate`。
- 无依据或缺条件：`rag_phase1_license_authenticity_no_answer`、`rag_phase1_quality_certificate_without_category_no_answer`。
- 误导问题：`rag_phase1_retired_policy_late_quality_certificate`、`rag_phase1_government_duty_as_internal_rule_no_answer`、`rag_phase1_voluntary_certification_overrides_policy`。

先逐题报告结果，再汇总三项：3 道正常题的必需依据是否进入 Top-5、5 道边界题是否按各自金标准正确处理、8 题中错误或无效引用数。边界题可能应纠正前提并引用现行制度，不是全部拒答。选取理由是两份制度足以覆盖材料检查与常见误用；其余 7 题涉及历史日期或外部法规知识，明确未覆盖。不能把这个子集结果称为完整 15 题成绩。

版本清单过滤另用旧制度和外部法规的候选元数据验证确实被排除；仅在正常语料中搜不到旧版本，不算验证了过滤。完成首版后，若出现具体漏检案例，可增加一次关键词与向量检索对比实验；是否采用混合检索由结果决定，不自动转成必做项。

## 最小实现方式

沿用 Python、FastAPI、Pydantic 和现有工程工具。先用模型供应商的官方 SDK 完成受限 tool calling 循环，不预设 LangGraph、多 Agent 或 MCP 服务。

工具调用尽量只读或做纯计算，失败后允许整次重新执行，不实现节点级恢复。保留本次输入、实际工具调用及结果、最终报告、耗时和可获得的 token 用量，不记录模型隐藏思维过程。演示运行与报告可先保存到已忽略的 `logs/agent-runs/`，不为此建立工作流平台。

前端采用一个工作台；接入现有 FastAPI 时沿用认证，不新增账号管理和角色流程。报告确认只记录用户对该报告的反馈，不触发已有审批接口或供应商资格变更。

## 暂停范围

多 Agent 分工、LangGraph 持久化恢复、采购例外、质量经理流程、规则编辑器、审批任务平台、RAG 多路融合、独立 EvidenceEngine、知识库增量治理和复杂评测大屏均退出当前必做范围。已有实现及数据保留，暂停继续扩建。

## 完成标准

1. 正常材料：从 PDF 提取事实、调用校验与检索工具，输出可查看原文的报告。
2. 缺失材料：Agent 明确追问；用户补充后重新检查，能看到前后结果。
3. 无制度依据：明确说明依据不足，不伪造引用、不声称准入批准。
4. 工具或模型失败：显示可理解的错误，达到预算上限后停止，可以重新发起。
5. 开发者能沿一次运行记录解释模型为何调用工具、参数如何校验、引用如何检查，并独立修改一项行为后验证。

实施顺序与进度见 [Agent 开发计划](VendorGuard-Agent开发计划.md)；历史方案不再作为实施要求。
