# VendorGuard 的前期调研与需求分析

> 本文保留原平台方案的领域调研与术语，不构成当前实现承诺。2026-09-08 起，实施范围以 [PRD](VendorGuard-PRD.md) 为准；下文的“一期”指历史平台方案。

> 内容类型：概念与调研参考
>
> 目标：解释 VendorGuard 为什么聚焦供应商准入与采购申请例外审批，并为规则、数据和 MVP 边界提供依据。

VendorGuard 使用公开资料完成桌面调研，并使用教学用模拟数据开发和演示。本文不是任何企业的采购制度，也不构成法律、质量或合规意见。

## 项目覆盖的业务问题

制造企业的采购既要保证物料供应，也要控制供应商资质、价格、质量和审批例外。供应商材料、制度和历史记录分散在 PDF、表格和邮件中时，采购人员容易遗漏材料、忽略证照临期，或难以说明例外审批的依据。

VendorGuard 将问题限定在两个采购前置控制点：

1. **供应商准入**：评估供应商是否满足进入合格供应商池的基础条件
2. **采购申请例外**：当采购申请使用当前不在 AVL 的供应商时，创建只适用于该 PR 的例外案件并路由给对应负责人审批

该范围覆盖采购开始前的关键控制，不试图实现完整的企业资源计划系统。

## 采购流程与一期边界

制造业采购到付款流程通常包含：

```text
需求信号 -> 采购申请（PR） -> 供应商选择 -> 采购订单（PO）
-> 审批与供应商确认 -> 收货 -> 三方匹配 -> 付款和结账
```

一期覆盖的路径为：

```text
供应商准入 -> 合格供应商池（AVL） -> 采购申请例外审批 -> 允许创建 PO
```

这里的“允许创建 PO”只表示 VendorGuard 输出本次 PR 可以继续的控制结果；一期不创建、不发送真实 PO。采购例外批准也不会改变供应商准入资格，其他 PR 仍需重新校验 AVL。

收货、发票匹配和付款属于后续 P2P 环节。它们需要库存、财务和应付账款模型，因此不进入 10 天高强度 MVP。

## 核心术语

| 术语 | 定义 | 项目中的含义 |
| --- | --- | --- |
| PR | Purchase Requisition，采购申请 | 需求部门发起采购需求的记录 |
| PO | Purchase Order，采购订单 | 一期仅判断是否允许创建，不生成或发送订单 |
| AVL | Approved Vendor List，合格供应商池 | 状态为 `approved` 的供应商可走常规采购 |
| 供应商准入 | 采购前对主体、资质、质量与履约能力的核验 | 一期的主流程 |
| 准入案件 | 一次供应商准入申请及其材料、风险和审批记录 | 有独立流程状态，不等同于供应商资格 |
| 供应商资格 | 供应商当前是否具备常规采购资格 | 仅当前有效的 `approved` 供应商进入 AVL |
| 采购例外案件 | PR 使用非 AVL 供应商时创建的单次审批案件 | 只对关联 PR 在批准范围和有效期内生效 |
| 限时豁免 | 人工在明确范围内暂时接受某项风险的决定 | 不删除规则命中，不自动改变供应商资格 |
| 审批矩阵 | 按品类、金额、风险和组织定义审批角色的规则 | 由 YAML 策略配置 |
| 三方匹配 | 对 PO、收货单和发票进行核对 | 二期范围 |

## 当前流程与改进目标

当前模拟流程中，采购人员通过邮件和表格收集材料，手动核对证照与报价，再通过邮件追踪审批。制度和历史案例分散，例外理由难以追溯。

目标流程如下：

```text
供应商准入：
申请与材料上传 -> 事实提取和材料完整性检查 -> 规则门禁
-> 制度与案例检索 -> 风险证据审校 -> 人工审批或补件 -> 更新 AVL 与审计归档

采购申请例外：
创建 PR -> 校验供应商资格 -> 创建例外案件 -> 规则与证据审查
-> 人工批准或拒绝 -> 仅对本次 PR 放行或终止 -> 到期与审计归档
```

## 角色与职责分离

| 角色 | 责任 | 约束 |
| --- | --- | --- |
| 采购专员 | 提交准入申请和 PR、补充材料、发起例外 | 不审批自己提交的准入或例外案件 |
| 采购经理 | 审批报价、履约和采购例外风险 | 不独自审批关键物料质量例外 |
| 质量经理 | 审批质量证书与关键物料风险 | 不改写报价或预算 |
| 管理员 | 管理规则版本、查看审计记录 | 不删除审计记录 |

## 教学规则与证据

下列阈值只服务于 MVP 演示。真实企业应由采购、质量和法务共同确认。

| 规则 | 条件 | 处理 | 证据 |
| --- | --- | --- | --- |
| `VEN-001` | 上传材料中的营业执照已过期、字段矛盾或无法判读 | 阻断或人工核验 | 营业执照字段或页码 |
| `VEN-002` | 按供应商品类要求的必填材料缺失 | 补件 | 品类材料要求与文件清单 |
| `VEN-003` | 质量证书剩余不足 90 天 | 质量复核 | 证书页码与制度条款 |
| `VEN-004` | 统一币种、单位、税口径和基准日期后，报价高于基准价 20% 以上 | 采购复核 | 报价单与基准价记录 |
| `VEN-005` | 有足够历史记录且准时交付率低于 90% | 采购复核 | 履约 CSV 行与样本数量 |
| `VEN-006` | 关键物料 | 采购与质量双审批 | 品类字段与审批矩阵 |
| `PR-001` | PR 使用当前不在 AVL 的供应商 | 创建单次例外审批 | PR、供应商资格快照与制度条款 |

这些规则只核验上传材料及项目内数据的一致性。未接入工商、认证机构或 ERP 等权威数据源时，系统不得将文档检查描述为主体真实性验证。ISO 9001 等质量材料是否必填由供应商品类配置决定，不对所有供应商一刀切。首次合作供应商没有历史履约记录时，应标记“历史数据不足”并转人工复核，而不是按低履约率处理。

## RAG、规则和人工审批的边界

| 层级 | 应处理的事项 | 示例 |
| --- | --- | --- |
| 确定性工具与规则 | 明确字段、计算、阈值和权限 | 证书剩余天数、报价偏离、审批路由 |
| 检索增强生成（RAG） | 制度依据、相似案例和处置建议 | 为临期证书风险引用制度条款 |
| 人工审批 | 接受风险、拒绝申请、授予时限豁免 | 质量经理批准续证豁免 |

RAG 不决定准入。检索无证据时，系统必须标记“证据不足”。规则命中、审批决定和豁免理由都需要保留审计记录。

解析器、检索或模型调用失败属于技术运行失败，应记录失败节点并允许重试；它与“已完成检索但没有足够业务证据”是两种不同结果。

## 采购例外的最小数据要求

一期的采购例外案件至少包含：PR 编号、申请人、物料品类、数量、金额与币种、紧急程度、目标供应商、未使用 AVL 供应商的原因、期望有效期和附件。审批决定必须记录批准范围、有效期、责任人和理由。

例外批准只放行关联 PR，不把供应商加入 AVL，也不能被其他 PR 复用。到期后尚未继续执行的 PR 必须重新审批。采购专员不能审批自己提交的例外；关键物料例外仍需要采购经理与质量经理分别作出决定。

## 模拟数据和评测边界

MVP 使用自制或公开模板衍生的供应商材料，包括基本信息、营业执照、按品类要求提供的质量证书、报价单和可选履约记录。先用 6 至 10 组材料跑通业务流程，再扩展到 20 组评测样本。知识库先使用 10 至 20 篇模拟或公开制度、SOP 和历史案例文档，基础闭环稳定后再扩展。

每项风险要关联材料来源和制度/案例引用。演示与测试不得使用真实供应商、合同、报价、联系人或生产数据。

## 演示案例

| 案例 | 关键事实 | 预期结果 |
| --- | --- | --- |
| 正常准入 | 品类要求的材料齐全，材料日期有效，报价和履约正常 | 采购经理确认，供应商进入 AVL |
| 补件后复核 | 缺证后补齐，证书剩余 60 天，完成口径统一后报价偏离 25% | 引用制度，采购与质量复核 |
| PR 例外 | 紧急关键物料 PR 使用未准入供应商，并提供单次采购理由和有效期 | 禁止直接创建 PO，采购与质量分别审批；批准仅对该 PR 生效 |
